Northstar uses API keys sent through the HTTP `Authorization` header using the Bearer scheme.

```http
Authorization: Bearer YOUR_API_KEY
```

For the **local mock only**, use `ns_demo_key`. This is intentionally a public demo token, not a secret. This is a test.

<Tabs>
  <Tab title="cURL">
    ```bash
    curl http://localhost:8787/v1/customers \
      -H "Authorization: Bearer ns_demo_key"
    ```
  </Tab>
  <Tab title="JavaScript">
    ```javascript
    const response = await fetch('http://localhost:8787/v1/customers', {
      headers: { Authorization: 'Bearer ns_demo_key' },
    });
    if (!response.ok) throw new Error(`Request failed: ${response.status}`);
    const { data } = await response.json();
    console.log(data);
    ```
  </Tab>
</Tabs>

## Best practices for production services

- Keep actual API tokens in server-side environment variables or secret managers.
- Do not embed privileged API tokens in public browsers, client apps, or version control.
- Rotate keys and use least-privilege permissions where your platform supports them.
- Treat a `401` response as an authentication failure. Refresh configuration before retrying.

<Warning>
  The fictional API does not provide real credential issuance, access controls, or key rotation. This page illustrates how to document those behaviors for a production API.
</Warning>
